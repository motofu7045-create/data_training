## 基本の考え方

### 3つは1本の流れにまとめる

| 目標 | 位置づけ |
| --- | --- |
| ③ プログラミング的思考 | 土台 |
| ② Python | 思考を形にする道具 |
| ① AWSのデータ分析基盤 | ゴール |

3つを別々に並行して進めると、どれも中途半端になりやすい。
「データを集めて、加工して、貯めて、分析する」仕組みを自分で1つ作り、それを少しずつ大きくしていくことで、3つを同時に鍛える。

### 「上流工程で通用する」とは

コードが書けること以上に、次のことができる状態を目指す。

- なぜその構成にしたかを説明できる（他の選択肢と比べてどうか）
- コスト・セキュリティ・運用まで考えて設計できる
- 要件を聞いて、作るものに落とし込める

そのために、手を動かすたびに「なぜそうしたか」を文書に残す（このリポジトリの `docs/` を使う）。

## 進め方（4段階）

今のスキルを踏まえ、Pythonの文法とAWSの知識は「ある」前提で進める。
一方で、段階2以降で毎日使う Linux・Docker・git は、段階1で自信をつけておく。

| 段階 | やること | 身につくもの | 目安 |
| --- | --- | --- | --- |
| 1. 基礎固め | pandas でのデータ加工、CSVを読んで集計する小さなスクリプト作り。SQLの中級（JOIN、集計、ウィンドウ関数）。Linux・Docker・git の基本操作を日常的に使う | ②③、Linux・Docker・git | 1〜2ヶ月 |
| 2. 手元で基盤を作る | Docker上にDB（PostgreSQL）を立てる。公開データを取ってきて加工し、DBに入れるETLをPythonで書く。git で管理する | ①②、Linux・Docker | 1〜2ヶ月 |
| 3. AWSに移す | 段階2の仕組みを S3・Lambda・Glue・Athena・RDS などで作り直す | ①、クラウド | 2〜3ヶ月 |
| 4. 上流の視点 | データモデル設計（スター・スキーマなど）、構成の比較、コストと運用の設計、設計書を書く | 上流工程の力 | 段階3と並行 |

### この順番にしている理由

- **いきなりAWSから始めない**: SAAで知っているサービスも、手元でETLの中身を理解しないまま使うと、設定作業を覚えるだけになりがち。仕組みを一度自分の手で作ってから、クラウドの何が便利なのかを体感するほうが、上流で説明できる力になる。
- **Linux・Docker・git は段階1で**: 段階2以降はこの3つを使わない日がない。自信がないまま先に進むと、本題（ETLや設計）より環境のトラブルに時間を取られるので、早めに慣れておく。
- **Python試験は段階1の区切り**: 基礎試験の次として、Python 3 エンジニア認定データ分析試験が段階1の到達目標にちょうど合う。
- **AWSの資格は段階3の区切り**: SAAは取得済みなので、次は AWS認定 データエンジニア アソシエイト（DEA）。目標①（データ分析基盤）にそのまま重なる。
- **Kaggleはほどほどに**: 目標が基盤づくりと上流工程なので、段階1〜2で分析の感覚をつかむ用途に留める。

### 習慣にすること

- コードを書く前に、処理の手順を日本語の箇条書きで書く（③の思考力を鍛える）
- 作ったものごとに「なぜそうしたか」を文書に残す

### 注意点

- AWSを触るときは、最初に予算アラートを設定する（消し忘れたリソースで請求が来るのを防ぐ）

## 今の仕事との関係（2026-10-02 時点）

- Salesforce で Apex を使う仕事になりそう。Salesforce アドミン資格（認定アドミニストレーター）の取得を推奨されている
- 2026年8〜9月は Salesforce の案件で環境を触っていた。アドミン資格は2026年10月中に取れる見込み
- Python を月に数時間使う案件の相談を受けている

### Salesforce は遠回りではない

企業のデータ分析基盤では、Salesforce は代表的な「データの取り込み元」の一つ。顧客や商談のデータを Salesforce から取り出し、データ基盤に集めて分析する仕組みはよく作られる。

- **アドミン資格**: オブジェクトや項目の関係（データモデル）、権限、データの流れを学ぶ。データ基盤側から Salesforce のデータを扱うときにそのまま役立ち、利用者の業務を理解して要件を整理する力にもつながる
- **Apex**: Java に近い言語。Python とは別だが、処理を組み立てる力（目標③）はそのまま鍛えられる
- **Salesforce ＋ AWS の連携**: Salesforce のデータを AWS（Amazon AppFlow や Glue で S3 へ）に取り込み、Athena で分析する、という仕組みは実務によくある形。段階3の題材にすると、今の仕事と目標①がつながり、社内でデータ基盤に関わるきっかけにもなりうる

### Python の案件は受ける

月に数時間でも、実務で Python を使った経験になる。ロードマップの「実務で関わる」への最初の一歩として受ける。

## 5年間のロードマップ

要件整理やレビューは、自習だけでは身につかない。実際の基盤や利用者の要望に触れた経験が必要になる。
そのため、**自習は最初の1年ほどで集中して進め、早めに実務でデータ基盤に関わる立場に入る**ことを軸にする。

| 時期 | 年齢 | 立ち位置 | やること |
| --- | --- | --- | --- |
| 1年目 | 24〜25歳 | 自習で土台を作る | Salesforce アドミン資格を取る（2026年10月）。段階1〜3を進める。DEA取得。このリポジトリを成果物（ポートフォリオ）にする。Python の案件で実務経験を積む |
| 2〜3年目 | 25〜27歳 | 実務で作る | データ基盤の構築・運用に実務で関わる（Salesforce のデータ連携から社内で関わる、異動、転職も選択肢）。ワークフロー管理やデータ品質など、現場の道具と課題を知る |
| 4〜5年目 | 27〜29歳 | 設計とレビューをする | 設計書を書き、他の人の設計やコードをレビューする。小さな案件をまとめる。利用者と話して要件を整理する経験を積む |
| 6年目 | 29〜30歳 | 要件整理をする側 | 企業のデータ分析基盤を作成・レビュー・改良できる状態 |

段階4（上流の視点）は1年目から少しずつ始め、2年目以降は実務の中で深める。

| 使うもの | 週あたり | 向いていること |

## 最初の1ヶ月の計画（2026年10月）

### アドミン資格の勉強量の見積もり（2026-10-02）

公式 Trailmix の教材を出題範囲別の要点にまとめた（[../salesforce_admin/notes/](../salesforce_admin/notes/)）結果、残りの勉強は **25〜30時間** と見積もる。

- Trailmix の目安時間は合計40時間を超えるが、大半はハンズオンの手順。試験に必要な知識は8ファイルに収まり、1周読むだけなら3〜4時間
- 8〜9月の実務経験と実力診断の結果から、ゼロから始める場合の目安（60〜80時間）の半分以下で足りると判断

| 内容 | 時間 | どこで |
| --- | --- | --- |
| まとめを理解しながら1周読む | 6〜8時間 | スマホ |
| 問題演習（公式の模擬試験、Claude が出す問題） | 10〜12時間 | スマホ |
| 間違えた分野の読み直し（2周目） | 4〜5時間 | スマホ |
| 弱点を Developer Edition で実際に触る（共有設定、レポート、承認プロセス、フロー） | 4〜6時間 | PC |

分野ごとの重さ:

| 重さ | 分野 |
| --- | --- |
| 重い | 01 設定（特に共有設定）、06 データと分析（合わせて配点32%） |
| 中くらい | 02 オブジェクトマネージャー、07 自動化、08 Agentforce |
| 軽い | 03 営業、04 サービス、05 生産性 |

**受験日を決める目安**: 問題演習で **80%以上を安定して取れる**ようになったら（合格ラインは68%）。
