# 学習方針の整理

最終更新: 2026-10-02

## 目標

次の3つを、上流工程で通用するレベルまで引き上げる。

1. 自分でAWS上にデータ分析基盤を作り、DBやETLなどを学ぶ
2. Pythonを用いたプログラミングができるようになる
3. プログラミング的な思考を学ぶ

## 現在のスキル（2026-10-02 時点）

| 分野 | 状況 |
| --- | --- |
| Python | Python 3 エンジニア認定基礎試験 取得済み |
| AWS | AWS認定 ソリューションアーキテクト アソシエイト（SAA）取得済み |
| SQL | 資格はないが基本は分かる |
| Linux・Docker・git | 触ったことはあるが自信がない |

## 基本の考え方

### 3つは1本の流れにまとめる

| 目標 | 位置づけ |
| --- | --- |
| ③ プログラミング的思考 | 土台 |
| ② Python | 思考を形にする道具 |
| ① AWSのデータ分析基盤 | ゴール |

3つを別々に並行して進めると、どれも中途半端になりやすい。
「データを集めて、加工して、貯めて、分析する」仕組みを自分で1つ作り、それを少しずつ大きくしていくことで、3つを同時に鍛える。

### 「上流工程で通用する」とは

コードが書けること以上に、次のことができる状態を目指す。

- なぜその構成にしたかを説明できる（他の選択肢と比べてどうか）
- コスト・セキュリティ・運用まで考えて設計できる
- 要件を聞いて、作るものに落とし込める

そのために、手を動かすたびに「なぜそうしたか」を文書に残す（このリポジトリの `docs/` を使う）。

## 進め方（4段階）

今のスキルを踏まえ、Pythonの文法とAWSの知識は「ある」前提で進める。
一方で、段階2以降で毎日使う Linux・Docker・git は、段階1で自信をつけておく。

| 段階 | やること | 身につくもの | 目安 |
| --- | --- | --- | --- |
| 1. 基礎固め | pandas でのデータ加工、CSVを読んで集計する小さなスクリプト作り。SQLの中級（JOIN、集計、ウィンドウ関数）。Linux・Docker・git の基本操作を日常的に使う | ②③、Linux・Docker・git | 1〜2ヶ月 |
| 2. 手元で基盤を作る | Docker上にDB（PostgreSQL）を立てる。公開データを取ってきて加工し、DBに入れるETLをPythonで書く。git で管理する | ①②、Linux・Docker | 1〜2ヶ月 |
| 3. AWSに移す | 段階2の仕組みを S3・Lambda・Glue・Athena・RDS などで作り直す | ①、クラウド | 2〜3ヶ月 |
| 4. 上流の視点 | データモデル設計（スター・スキーマなど）、構成の比較、コストと運用の設計、設計書を書く | 上流工程の力 | 段階3と並行 |

### この順番にしている理由

- **いきなりAWSから始めない**: SAAで知っているサービスも、手元でETLの中身を理解しないまま使うと、設定作業を覚えるだけになりがち。仕組みを一度自分の手で作ってから、クラウドの何が便利なのかを体感するほうが、上流で説明できる力になる。
- **Linux・Docker・git は段階1で**: 段階2以降はこの3つを使わない日がない。自信がないまま先に進むと、本題（ETLや設計）より環境のトラブルに時間を取られるので、早めに慣れておく。
- **Python試験は段階1の区切り**: 基礎試験の次として、Python 3 エンジニア認定データ分析試験が段階1の到達目標にちょうど合う。
- **AWSの資格は段階3の区切り**: SAAは取得済みなので、次は AWS認定 データエンジニア アソシエイト（DEA）。目標①（データ分析基盤）にそのまま重なる。
- **Kaggleはほどほどに**: 目標が基盤づくりと上流工程なので、段階1〜2で分析の感覚をつかむ用途に留める。

### 習慣にすること

- コードを書く前に、処理の手順を日本語の箇条書きで書く（③の思考力を鍛える）
- 作ったものごとに「なぜそうしたか」を文書に残す

### 注意点

- AWSを触るときは、最初に予算アラートを設定する（消し忘れたリソースで請求が来るのを防ぐ）
