# 学習方針の整理

最終更新: 2026-10-02

## 目標

次の3つを、上流工程で通用するレベルまで引き上げる。

1. 自分でAWS上にデータ分析基盤を作り、DBやETLなどを学ぶ
2. Pythonを用いたプログラミングができるようになる
3. プログラミング的な思考を学ぶ

## 基本の考え方

### 3つは1本の流れにまとめる

| 目標 | 位置づけ |
| --- | --- |
| ③ プログラミング的思考 | 土台 |
| ② Python | 思考を形にする道具 |
| ① AWSのデータ分析基盤 | ゴール |

3つを別々に並行して進めると、どれも中途半端になりやすい。
「データを集めて、加工して、貯めて、分析する」仕組みを自分で1つ作り、それを少しずつ大きくしていくことで、3つを同時に鍛える。

### 「上流工程で通用する」とは

コードが書けること以上に、次のことができる状態を目指す。

- なぜその構成にしたかを説明できる（他の選択肢と比べてどうか）
- コスト・セキュリティ・運用まで考えて設計できる
- 要件を聞いて、作るものに落とし込める

そのために、手を動かすたびに「なぜそうしたか」を文書に残す（このリポジトリの `docs/` を使う）。

## 進め方（4段階）

| 段階 | やること | 身につくもの | 目安 |
| --- | --- | --- | --- |
| 1. 基礎 | Pythonの基本と、CSVを読んで集計する小さなスクリプト作り。SQLの基本 | ②③ | 1〜2ヶ月 |
| 2. 手元で基盤を作る | Docker上にDB（PostgreSQL）を立てる。公開データを取ってきて加工し、DBに入れるETLをPythonで書く | ①②、Linux・Docker | 1〜2ヶ月 |
| 3. AWSに移す | 段階2の仕組みを S3・Lambda・Glue・Athena・RDS などで作り直す | ①、クラウド | 2〜3ヶ月 |
| 4. 上流の視点 | データモデル設計（スター・スキーマなど）、構成の比較、コストと運用の設計、設計書を書く | 上流工程の力 | 段階3と並行 |

### この順番にしている理由

- **いきなりAWSから始めない**: 手元でETLの中身を理解しないままクラウドに行くと、サービスの設定作業を覚えるだけになりがち。仕組みを一度自分の手で作ってから、クラウドの何が便利なのかを体感するほうが、上流で説明できる力になる。
- **Python試験は段階1の区切り**: Python 3 エンジニア認定データ分析試験は、段階1の到達目標にちょうど合う。
- **AWSの資格は段階3の区切り**: AWS認定のソリューションアーキテクト アソシエイト（SAA）とデータエンジニア アソシエイト（DEA）は、上流工程の話をする共通言語としても役立つ。
- **Kaggleはほどほどに**: 目標が基盤づくりと上流工程なので、段階1〜2で分析の感覚をつかむ用途に留める。

### 習慣にすること

- コードを書く前に、処理の手順を日本語の箇条書きで書く（③の思考力を鍛える）
- 作ったものごとに「なぜそうしたか」を文書に残す

### 注意点

- AWSを触るときは、最初に予算アラートを設定する（消し忘れたリソースで請求が来るのを防ぐ）

- [ ] 1週間に使える学習時間
- [ ] 目的と期限（仕事で必要、転職を考えている、などの背景と、いつまでにという期限）
