## 3-1. 取引先と取引先責任者

| 用語 | 意味 |
| --- | --- |
| 取引先（法人取引先） | 取引をする**会社** |
| 取引先責任者 | 取引先で働く**人** |
| **個人取引先** | 自営業者や個人の消費者など、**1人の人物**と取引するときの特別な取引先。**取引先責任者を持たない** |

### 取引先と取引先責任者の関係（3種類）

| 関係 | 機能 |
| --- | --- |
| 会社と、そこで働く人 | 取引先責任者は**必ず1つの取引先に直接関連付ける** |
| 人と、間接的に関わる他の会社 | **取引先責任者-to-複数取引先**（1人を複数の取引先に関連付ける。重複レコードを作らずに済む。**システム管理者が有効化する**必要がある） |
| 会社と、他の会社 | **取引先階層**（親取引先を設定すると、取引先のファミリーツリーが表示される） |
| 会社と、自社の担当者 | **取引先チーム** |

### ベストプラクティス

- 取引先の**命名規則**を決めて守る
- 取引先責任者は**必ず取引先に関連付ける**。取引先のない取引先責任者（非公開の取引先責任者）は、**所有者とシステム管理者以外には見えない**
- 30・60・90日間活動がない取引先や取引先責任者をレポートで見つける
- 退職・異動した人が所有する取引先は、新しい所有者に移す
- 複数拠点がある会社は、**1つのグローバル取引先にまとめるより、拠点ごとに取引先を作る**のが推奨（所有権、階層、共有設定、詳細なレポートに対応しやすい）

出典: [取引先と取引先責任者](https://trailhead.salesforce.com/ja/content/learn/modules/accounts_contacts_lightning_experience/accounts-and-contacts-lightning)、[取引先と取引先責任者のリレーション](https://trailhead.salesforce.com/ja/content/learn/modules/accounts_contacts_lightning_experience/understand-account-and-contact-relationships-lightning)

## 3-2. リード

- **リード**: 関心を示したが、まだ顧客になっていない見込み客（個人または会社）。評価がまだの段階
- リードの入手元: 紹介、Web サイトの問い合わせフォーム、展示会、広告など
- リードの追加方法: 手入力、ファイルのインポート、**Web-to-リード**（Web サイトのフォームから自動で作成）
- リードの割り当て: 地域やテリトリーなどの条件で**自動的に割り当てる**、または**キュー**に入れる

### リードの取引開始（試験に出やすい）

リードの取引を開始すると、リードの情報から次が作られる。

| 作られるもの | 備考 |
| --- | --- |
| 取引先（法人取引先） | |
| 取引先責任者 | |
| 商談 | **任意**（作らないこともできる） |

- 個人取引先が有効で、リードに**会社名がない**場合は、**個人取引先**と商談に変換される

### リードインテリジェンスビュー

[リード] タブの中で、リードの絞り込み、活動の状況の確認（過去30日に活動がない、期限切れの活動がある、など）、アクションができる。

出典: [リードで潜在的な顧客を追跡する](https://trailhead.salesforce.com/ja/content/learn/modules/leads_opportunities_lightning_experience/create-and-convert-leads-lightning)

## 3-3. 商談

- **商談**: 評価済みで、成立の見込みがある**案件**。期待収益、フェーズ、完了予定日、確度などを持つ
- 商談は**フェーズ**を進んでいく（例: 見込み客 → 評価 → ニーズ分析 → 価値提案 → 交渉 → 商談成立／不成立）。各フェーズに確度（%）が結び付いている
- **商談の取引先責任者の役割**: 商談に関わる取引先責任者と、その役割（意思決定者など）を記録する。**主取引先責任者**を1人指定できる
- **パイプラインインスペクション**: パイプライン全体（件数、金額、フェーズ、週ごとの変化、AI のインサイト）を1か所で見る

### 商談チーム と 取引先チーム

| | 商談チーム | 取引先チーム |
| --- | --- | --- |
| 期間 | **一時的**（その商談の成立まで） | **長期的**（顧客との関係） |
| 前提 | システム管理者が**チームセリング**を有効化 | |
| デフォルト | デフォルトの商談チームを作ると、新しい商談に自動で追加できる | デフォルトの取引先チームを作れる |

### 商談分割（試験に出やすい）

| 種類 | 合計 | 使う場面 |
| --- | --- | --- |
| **収益分割** | **100%ちょうど**（超えられない） | 報酬が収益に直結する場合。過剰な報酬を防ぐ |
| **オーバーレイ分割** | **100%を超えてよい** | 収益とは別に、付加的な貢献（デモをした技術者など）を認める |
| 商談商品分割 | 収益分割に使えば100%まで、オーバーレイ分割に使えば100%超も可 | 商品ごとに貢献を分ける |

- 分割を追加・調整できるのは、**商談の所有者**か、ロール階層で**所有者より上位**のユーザー
- 所有者はデフォルトで収益の100%を受け取る

出典: [商談での作業](https://trailhead.salesforce.com/ja/content/learn/modules/leads_opportunities_lightning_experience/work-your-opportunities)、[チームでの販売とクレジットの分割](https://trailhead.salesforce.com/ja/content/learn/modules/leads_opportunities_lightning_experience/sell-as-a-team-and-split-the-credit)

## 3-4. パスと Kanban

### パス

- レコードが今どの段階にいるかを、ページ上部に矢印で表示する
- **システム管理者が有効化して設定する**必要がある
- パスのステップごとに、**重要な項目を最大5個**、**成功へのガイダンスを最大1,000文字**設定できる
- **紙吹雪**: 特定のフェーズ（商談成立など）になったときに表示できる
- パスは**オブジェクト × レコードタイプ**ごとに作る
- 設定する場所: [設定] → 「パス設定」

### セールスプロセスとパスの作り方（流れ）

1. **セールスプロセス**を作る（使うフェーズを選ぶ）。[設定] → 「セールスプロセス」
2. そのセールスプロセスを使う**レコードタイプ**を作る
3. そのレコードタイプに**パス**を作る

### Kanban ビュー

- リストビューを**カード形式**で表示する。商談はデフォルトで**フェーズ別**の列
- カードを**ドラッグ**して次のフェーズに進められる
- 列の分け方や、列の上に出す合計（金額、期待収益など）を変えられる
- 検索条件やグラフも使える
- **すべてのユーザー**が、ほとんどのオブジェクトで使える（パスと違い、管理者の設定は不要）

出典: [パスと Kanban](https://trailhead.salesforce.com/ja/content/learn/modules/leads_opportunities_lightning_experience/visualize-success-with-path-and-kanban)、[チームのセールスパスのカスタマイズ](https://trailhead.salesforce.com/ja/content/learn/projects/customize-a-sales-path-for-your-team)

## 3-5. キャンペーン

- **キャンペーン**: マーケティング活動（メール、広告、展示会、デモなど）をまとめる入れ物。生成したリード数、パイプライン、成立した商談を分析できる
- キャンペーンを作るには、ユーザーの「**マーケティングユーザー**」チェックボックスがオンになっている必要がある

### キャンペーン階層

- 「**親キャンペーン**」項目で階層を作る。**最大5階層**（多くの会社は3階層で十分）
- 例: 1階層目＝全社の戦略、2階層目＝製品の立ち上げ、3階層目＝個々のメールやデモ
- レスポンス数や取引開始済みのリード数などの**キャンペーン結果は親に積み上げ集計される**
- キャンペーンの種類ごとに**レコードタイプ**を作ると、種類ごとに違う項目を追跡できる

### キャンペーンメンバー

- メンバーにできるもの: **リード、取引先責任者、取引先、個人取引先**
- 追加の方法: レコードの詳細ページ、取引先の取引先責任者関連リスト、リストビュー、レポートの結果、**データインポートウィザード**
- **キャンペーンメンバーの状況**: キャンペーンの種類ごとに状況のセットを決める（例: メール＝送信済み・返信あり・購入済み、デモ＝招待済み・参加）。どの状況を「**レスポンスあり**」として数えるかを指定できる

### キャンペーンのレポート

| レポート | わかること |
| --- | --- |
| Campaigns with Contacts / with Leads | キャンペーンの対象者 |
| Campaigns with Campaign Members | 各キャンペーンに反応したメンバー数 |
| Campaigns with Opportunities | キャンペーンから生まれた商談と収益 |

出典: [キャンペーンの基本](https://trailhead.salesforce.com/ja/content/learn/modules/campaign_basics)
