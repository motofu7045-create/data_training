## 5-1. Chatter の基本

- **Chatter フィード**: パブリッシャー（投稿の入力欄）と、投稿・アンケート・質問・コメントなどで構成される
- 投稿へのアクセス権があれば、コメント・いいね!・共有・ブックマーク・ミュートができる
- 投稿を編集できるのは、作成者と一部の権限を持つユーザー
- **変更追跡フィード（FTC）**: レコードの更新についてシステムが自動で作る投稿。投稿者、グループの所有者・マネージャー、「すべてのデータの編集」権限を持つユーザーが削除できる

### Chatter のメール通知

| 設定 | 内容 |
| --- | --- |
| 選択メールを許可 | 全ユーザーに Chatter のメール通知を有効にする |
| メール返信を許可 | 通知メールへの返信で投稿できる |
| メールによる投稿を許可 | メールでグループに投稿できる |

- ユーザーは自分で通知の設定を上書きできる（受け取るかどうか、何で通知するか、頻度）
- 通知が多すぎないように、「@メンションされたときだけ通知」を勧めるとよい

### Chatter 設定（[設定] → 「Chatter 設定」）の主なもの

| 設定 | 内容 |
| --- | --- |
| Chatter の有効化 | 組織で Chatter を使えるようにする（Lightning Experience では無効にしてもグローバル検索は使える） |
| グループ内のレコードを許可 | グループにレコードを関連付けられる |
| **リストに記載しないグループを有効化** | **デフォルトは無効**。有効化には「リストに記載しないグループを管理」権限が必要 |
| 外出中 | ユーザーが外出中メッセージを設定できる |
| **承認の投稿** | 承認申請をユーザーのフィードに投稿する |
| 同僚の招待 | ライセンスのない同僚を Chatter に招待できる（プロファイル・ファイル・グループだけ見られる） |
| 顧客の招待 | 自分が所有・管理する**非公開グループ**に顧客を招待できる |
| 投稿の固定 | トピックやグループのフィードの上部に投稿を**3つまで**固定できる（権限はプロファイルか権限セットで付ける） |

出典: [Chatter の使用開始](https://trailhead.salesforce.com/ja/content/learn/modules/lex_implementation_chatter/lex_implementation_chatter_intro)

## 5-2. Chatter グループ（試験に出やすい）

| 種類 | 誰が見られるか・参加できるか |
| --- | --- |
| **公開** | **全従業員**が見られて参加できる。誰でも投稿・コメント・ファイル追加ができる |
| **非公開** | **参加申請**が必要。メンバーだけが投稿できる。メンバー以外は写真と説明だけ見える。**顧客（外部メンバー）を招待できる** |
| **リストに記載しない** | **招待のみ**で参加。リストビューや検索結果に出ない。メンバー以外には見えない。招待できるのは所有者とマネージャー |
| ブロードキャストのみ | 所有者とマネージャーだけが投稿できる（メンバーはコメントのみ）。どの種類のグループにも設定できる |

- 所有者は**1人**、マネージャーは**複数**設定できる。マネージャーは所有者と同じ管理作業ができる
- **アーカイブ**すると投稿・ファイル共有ができなくなる（過去の投稿は見られる）
- グループごとにメールアドレスが作られる

出典: [Chatter グループ](https://trailhead.salesforce.com/ja/content/learn/modules/lex_implementation_chatter/lex_implementation_chatter_groups)

## 5-3. フィード追跡

- レコードの項目の値が変わったときに、フィードで通知する
- **Lightning Experience では、オブジェクトで Chatter を使うにはフィード追跡を有効にする必要がある**（例外: グループ、サイト、ユーザーオブジェクト）
- 追跡できる項目は**1つのオブジェクトで最大20項目**
- 共有ルールと項目レベルセキュリティが効く。レコードにアクセスできないユーザーには変更の通知は表示されない
- **45日**を過ぎても「いいね!」もコメントもない変更追跡フィードは**自動で削除**される（項目履歴管理の監査履歴は残る）
- 同じレコードの変更追跡フィードが一定時間内（デフォルト1,440分）に**3つ以上**できると、まとめて表示される（バンドル）
- 設定する場所: [設定] → 「フィード追跡」

出典: [フィード追跡](https://trailhead.salesforce.com/ja/content/learn/modules/lex_implementation_chatter/lex_implementation_chatter_feed_tracking)

## 5-4. Chatter での承認

承認申請を Chatter の投稿として送れる。

1. Chatter 設定で**承認の投稿**を有効にする
2. **承認投稿テンプレート**を作る（投稿に出すレコードの項目を決める）。「アプリケーションのカスタマイズ」権限が必要
3. 承認プロセスの対象オブジェクトの**フィード追跡を有効にする**

- 投稿が表示される場所: 承認者のフィード、申請者のプロファイル、承認レコードのフィード、承認レコードをフォローしているユーザーのフィード
- ユーザーは自分の設定で、承認申請を投稿として受け取らないようにできる（メールは届く）

出典: [Chatter フィードからのレコードの承認](https://trailhead.salesforce.com/ja/content/learn/modules/lex_implementation_chatter/lex_implementation_chatter_approvals)

## 5-5. Chatter の導入

- 進め方: **支援者**（担当役員、コミュニティマネージャーなど）を決める → **使用事例**を明らかにする → **コミュニケーション計画**を作る → **ルール（チャチケット）**を伝える → 結果を測る
- リリースは、休日や繁忙期を避け、営業時間後に有効にするのがよい
- 2010年6月22日より後に作られた組織では、Chatter は**デフォルトで全ユーザーに有効**
- **全員に同時にリリース**するのが推奨。**プロファイルベースのリリース**は、大規模な組織や規制のある組織に向く（Salesforce に有効化を依頼し、「Chatter を有効化」権限で制御する）
- 結果の測定: AppExchange の「Salesforce Chatter Dashboards」
- フォローの上限は**500件**（「Chatter Unfollow Rules」アプリで自動フォロー解除ができる）

出典: [ロールアウト戦略の作成](https://trailhead.salesforce.com/ja/content/learn/modules/lex_implementation_chatter/lex_implementation_chatter_adoption)

## 5-6. AppExchange（AgentExchange）

- アプリ・エージェント・コンポーネントなどの Salesforce 公式マーケットプレイス
- リスティングの種類: **ソリューション**（すぐ使える機能拡張）と**コンサルタント**（カスタムソリューションの構築・実装）
- 価格: 無料のものも多い。有料は一括払いかサブスクリプション

### 戦略を立てるときの質問

- すぐ統合できるもの（ソリューション）か、構築を手伝ってほしい（コンサルタント）か
- 必須の機能と、あれば便利な機能は何か
- 予算、使う人、テストできる環境、必要な製品・エディションとの互換性

### 試用の方法

| 種類 | 内容 |
| --- | --- |
| 機能制限トライアル | プロバイダーが用意した**参照のみ**の組織で試す |
| Sandbox トライアル | 自社の本番環境のコピーで試す |
| Trialforce トライアル | **書き込み可能**な組織で試す。購入すればそのまま使い続けられる |

### 管理パッケージ と 未管理パッケージ（試験に出やすい）

| | 管理パッケージ | 未管理パッケージ |
| --- | --- | --- |
| カスタマイズ | コードやメタデータは**見られない・変えられない** | **変えられる** |
| アップグレード | プロバイダーが**自動で**アップグレードできる | **アンインストールして新しいバージョンを入れ直す**必要がある |
| 組織の制限 | アプリ・タブ・オブジェクトの**制限に含まれない** | **制限に含まれる** |

### インストール

- まず **Developer Edition か Sandbox** でテストしてから本番にインストールする
- アクセス権を付ける対象: **システム管理者のみ／全ユーザー／特定のプロファイル**。迷ったらシステム管理者のみ
- インストール後は [設定] → 「インストール済みパッケージ」で詳細確認やアンインストールができる
- 問題があったら**プロバイダーに直接問い合わせる**
- レビューは Salesforce が選別せず、すべて掲載される

出典: [AgentExchange の基本](https://trailhead.salesforce.com/ja/content/learn/modules/appexchange_basics)
